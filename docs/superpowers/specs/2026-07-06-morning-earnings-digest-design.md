# Spec: สรุปงบเช้า (Morning Earnings Digest)

วันที่: 2026-07-06 • สถานะ: อนุมัติแล้ว รอ implement

## 1. เป้าหมาย

ช่วงฤดูงบ (ปลาย ก.พ. / พ.ค. / ส.ค. / พ.ย.) บริษัทแจ้งงบวันละหลายสิบถึงร้อยตัว
แจ้งเตือนเดิมมาเป็นชิ้นๆ ทุก 10 นาทีช่วงเย็น ผู้ใช้ต้องไล่อ่านย้อนเองตอนเช้า
→ เพิ่ม **ข้อความสรุปเดียวตอนเช้า** ที่รวบหุ้นแจ้งงบตั้งแต่เย็นวาน+เช้านี้
เรียงลำดับตามความน่าสนใจ (%YoY) ให้เสร็จ = "รายชื่อตัวที่ต้องเปิดดูปฏิกิริยาวันนี้"
ตรงกับ workflow เทรดหลังงบ (วันตอบรับคือวันนี้)

ข้อจำกัดสำคัญ: **ห้ามยิง Playwright เพิ่ม** — ใช้ข้อมูลที่ระบบสะสมไว้แล้วเท่านั้น
และ**ผู้ใช้มักเปิดคอมราว 09:30** ดังนั้น job เวลาตายตัวอย่างเดียวไม่พอ
ต้องมีการส่งตอนเปิดบอทด้วย (ดู §5)

## 2. ขอบเขต

ทำ:
- job สรุปงบเช้า 08:55 ทุกวันทำการ
- startup digest: ส่งตอนเปิดบอทถ้าวันนั้นยังไม่ได้ส่ง
- คำสั่งข้อความ `สรุปงบ` / `สรุปงบ N`
- ไฟล์ log ใหม่ `filings_log.csv` (ใครแจ้งงบเมื่อไหร่ — เก็บทั้งตัวที่อ่านตัวเลขไม่ได้)
- ไฟล์สถานะใหม่ `digest_state.json` (กันส่งซ้ำในวันเดียว)
- อัปเดตเอกสาร: `CLAUDE.md`, `วงจรระบบ.txt`, `คู่มือการใช้งาน.txt`, help text ในบอท

ไม่ทำ (เฟสถัดไป):
- ปฏิทินงบรวมศูนย์, ออโตเมชันหลังงบ, วิเคราะห์ F45 เชิงลึก
- ไม่แก้ logic ดึงข่าว Playwright (`fetch_company_news`, `fetch_news_details`)
- ไม่เปลี่ยน schema ไฟล์เดิมใดๆ (`news_seen.json`, `earnings_results.csv`, ฯลฯ)
- ไม่แตะ `stock_core.py`

## 3. แหล่งข้อมูล

1. **`earnings_results.csv`** (มีอยู่แล้ว, เขียนโดย `set_news._log_f45_result`)
   คอลัมน์: `news_datetime, symbol, period, year, profit_mb, profit_prior_mb, yoy_pct, summary`
   กันซ้ำต่อ (symbol, period, year) แล้ว — ฉบับ "แก้ไข" ไม่โผล่ซ้ำ
2. **`filings_log.csv`** (ใหม่) คอลัมน์: `news_datetime, symbol, kinds`
   - เขียนต่อท้ายใน `set_news.check_new_earnings_news()` ณ จุดเดียวกับที่บันทึก
     `seen[it["id"]]` (บรรทัด ~407) — บันทึกทุกข่าวงบที่ยังไม่เคยเห็น
     รวมข่าวเก่าที่เกิน `max_age_hours` ด้วย (เป็นบันทึกการแจ้งงบ ไม่ใช่การแจ้งเตือน)
   - `kinds` คั่นด้วย `/` เช่น `F45/งบการเงิน` — หนึ่งแถวต่อหนึ่งข่าว
     (หุ้นเดียวหลายข่าว = หลายแถว ผู้อ่านต้อง group เอง)
   - encoding `utf-8-sig` + เขียน header เมื่อสร้างไฟล์ใหม่ (ตามแบบ `_log_f45_result`)
   - เขียนพลาด (เช่นไฟล์เปิดค้างใน Excel) ต้องเงียบ ไม่ล้ม caller
   - หมายเหตุ: ไฟล์นี้เริ่มสะสมหลัง deploy — ช่วงแรกกลุ่ม 📄 (§4) จะยังไม่ครบ ยอมรับได้

ฟังก์ชันอ่านใหม่ใน `set_news.py`:
- `load_results_since(dt)` → list ของ dict จาก `earnings_results.csv` ที่
  `news_datetime >= dt` (แปลง profit เป็น float, yoy_pct เป็น float หรือ None)
- `load_filings_since(dt)` → dict `{symbol: {"datetime": ..., "kinds": [...]}}`
  จาก `filings_log.csv` (เก็บเวลาล่าสุดต่อ symbol, รวม kinds)
- ทั้งคู่: ไฟล์ไม่มี/อ่านพัง → คืนค่าว่าง ไม่โยน exception

## 4. รูปแบบข้อความสรุป

HTML (escape ทุกค่าจากภายนอกด้วย `html.escape`), ส่งผ่าน `_send_long`/`_reply_long`

```
🌅 <b>สรุปงบเช้านี้</b> — พฤ 06/08 (แจ้งงบตั้งแต่เย็นวาน 24 บริษัท)

🔥 <b>งบโตแรง — อยู่ใน universe/ลิสต์</b> (3)
1. AOT ⭐  Q3/2569: กำไร 4,120.0 ลบ. (+52% YoY)
2. TIDLOR  Q3/2569: พลิกเป็นกำไร 512.3 ลบ.
3. BDMS  Q3/2569: กำไร 3,890.5 ลบ. (+38% YoY)

🔥 <b>งบโตแรง — นอก universe</b> (4)
4. ...

📊 <b>มีตัวเลขแต่ไม่เข้าเกณฑ์โตแรง</b> (9)
8. KBANK  Q3/2569: กำไร 12,400.0 ลบ. (+18% YoY)
...

📄 แจ้งงบแล้วแต่ยังอ่านตัวเลขไม่ได้ (8):
AAA, BBB, CCC, ...

ดูปฏิกิริยาราคา: พิมพ์ชื่อหุ้น • เฝ้าตัวไหน: <code>ติดตาม XXX</code>
ตัวที่ตอบรับดีจะติดสแกนรอบ 17:30 วันนี้
```

กติกา:
- **กลุ่ม**: (1) 🔥 โตแรง ∩ (universe ∪ watchlist) (2) 🔥 โตแรง นอกนั้น
  (3) 📊 มีตัวเลขไม่โตแรง (4) 📄 อยู่ใน filings_log แต่ไม่อยู่ใน results ของช่วงนั้น
- **โตแรง** = นิยามเดิมของระบบ (`f45_is_strong`): `profit_mb > 0` และ
  (`profit_prior_mb <= 0` [พลิกเป็นกำไร] หรือ `yoy_pct >= 30`)
  — คำนวณจากคอลัมน์ CSV โดยตรง ห้าม hardcode เกณฑ์ใหม่
- **การเรียงในกลุ่ม 1-2**: พลิกเป็นกำไรอยู่บนสุด (เรียงตาม profit_mb มาก→น้อย)
  ตามด้วยที่เหลือเรียง yoy_pct มาก→น้อย • กลุ่ม 3: yoy_pct มาก→น้อย (None ไว้ท้าย)
- **เลขลำดับต่อเนื่อง**ข้ามกลุ่ม 1→3 (กลุ่ม 📄 ไม่มีเลข แสดงเป็นชื่อคั่น comma
  เกิน 30 ตัวตัดเป็น `...(+N)` ตามแบบ `build_news_alert_text`)
- ⭐ เฉพาะตัวที่อยู่ใน watchlist (`stock_core.get_watchlist()`),
  universe จาก `scanner.load_universe()`
- บรรทัดตัวเลขใช้ summary ที่มีอยู่แล้วในคอลัมน์ `summary` ของ CSV
  (ผลของ `format_f45_summary`) — ไม่ต้อง format ใหม่
- กลุ่มไหนว่าง → ไม่แสดงหัวข้อกลุ่มนั้น
- header: วันแบบย่อไทย (จ/อ/พ/พฤ/ศ/ส/อา) + dd/mm
  - โหมดปกติ: `(แจ้งงบตั้งแต่เย็นวาน N บริษัท)` — N = จำนวน symbol ทั้งหมด (ทุกกลุ่มรวมกัน)
  - โหมด `สรุปงบ N`: `(ย้อนหลัง N วัน, M บริษัท)`

## 5. ช่วงเวลาข้อมูล (window) และการส่ง

- **window ปกติ** = ตั้งแต่ **09:00 ของวันทำการก่อนหน้า** จนถึงตอนนี้
  - วันทำการก่อนหน้า = ถอยจากวันนี้ทีละวัน ข้ามเสาร์-อาทิตย์ และวันหยุดตาม
    `_is_market_holiday` (มีอยู่แล้วใน telegram_bot.py, อ่าน `holidays.txt`)
  - ผล: เช้าวันจันทร์ครอบคลุมศุกร์เย็น+เสาร์+อาทิตย์อัตโนมัติ
- **job รายวัน 08:55** (`DIGEST_HOUR=8, DIGEST_MINUTE=55` ตามแบบ constant เดิม):
  - ข้ามเสาร์-อาทิตย์และวันหยุดตลาด (แบบเดียวกับ `heartbeat_job`/`news_monitor_job`)
  - ไม่มีหุ้นแจ้งงบใน window → **ไม่ส่งอะไรเลย** และ**ไม่**บันทึกสถานะ
  - ส่งสำเร็จ → บันทึก `digest_state.json` = `{"last_sent": "YYYY-MM-DD"}`
- **startup digest**: ลงทะเบียน `run_once(startup_digest_job, when=300)`
  (300 วินาที — ให้ startup catch-up [วินาที 20] และ news poll รอบแรก [วินาที 120]
  ทำงานจบก่อน ข้อมูลเช้านี้จะได้อยู่ใน CSV แล้ว)
  เงื่อนไขส่ง (ต้องครบทุกข้อ): วันทำการ • `digest_state.last_sent != วันนี้` •
  เวลาปัจจุบัน < 16:30 • มีหุ้นแจ้งงบใน window → ส่ง + บันทึกสถานะ
- ผู้ใช้เปิดคอม ~09:30 → บอทเปิด → สรุปมาถึงราว 09:35 ก่อนตลาดเปิด 10:00
- อ่าน/เขียน `digest_state.json` พังต้องไม่ล้ม job (default = ยังไม่เคยส่ง)

## 6. คำสั่งข้อความ `สรุปงบ`

ใน `handle_text` (วางใกล้แขนง "ข่าวงบ"):
- `สรุปงบ` → window ปกติ (§5) • `สรุปงบ 3` → ย้อน 3 วันจากตอนนี้ (clamp 1..7)
- ตอบเสมอแม้ไม่มีข้อมูล: `📭 ไม่มีบริษัทแจ้งงบตั้งแต่ {วันเวลาเริ่ม window} ครับ`
- **ไม่**แตะ `digest_state.json` (เรียกดูซ้ำได้ไม่จำกัด)
- ไม่ยิงเครือข่ายใดๆ — อ่านจากไฟล์ล้วนๆ ตอบได้ทันทีไม่ต้องมีข้อความ "⏳ กำลัง..."
- เพิ่มบรรทัดใน `cmd_help` หมวดข่าวงบ: `• <code>สรุปงบ</code> — สรุปหุ้นแจ้งงบเมื่อวาน+เช้านี้ เรียงตามกำไรโต (สรุปงบ 3 = ย้อน 3 วัน)`

## 8. ข้อผิดพลาดและกรณีขอบ

- CSV อ่านพัง/เปิดค้างใน Excel → ส่วนนั้นเป็นค่าว่าง สรุปเท่าที่มี ห้ามล้ม job
- แถว CSV เสีย (คอลัมน์ขาด/parse ไม่ได้) → ข้ามแถวนั้น
- symbol อยู่ทั้ง results และ filings ใน window → แสดงเฉพาะฝั่งมีตัวเลข (ไม่ซ้ำใน 📄)
- ข้อความเกิน 3900 ตัวอักษร → `_send_long` ตัดตามบรรทัดให้อยู่แล้ว
- จำนวนบริษัทใน 📊 ไม่จำกัดจำนวน (ให้ `_send_long` จัดการ) — ห้ามตัดข้อมูลเงียบๆ

## 9. สไตล์โค้ด
